Part of: app
Read when: you run or extend the browser checks for the saves: top 10, name entry, game-over messages, BEST and the filled leaderboard (DRA-126).

## Rules

Integration checks for DRA-126, on top of the required browser checks and every earlier check, as reworded below (all must still pass). Each check starts in a fresh page unless it says otherwise. Background:
- "Clear the saves": with `browser_evaluate`, `localStorage.removeItem(<SAVE_KEY>)`, then reload. "Preload the saves with X": `localStorage.setItem(<SAVE_KEY>, X)`, then reload. `<SAVE_KEY>` is the committed `app.saves.SAVE_KEY`. Every preloaded X follows `docs/contracts/schemas/save-data.schema.json` unless the check says it is broken.
- "A strong list": ten entries `{"nickname": "TOP", "score": 999999999, "level_reached": 8}`, `"last_nickname": "TOP"`. No run beats it.
- The texts, sizes, boxes, colors and x below are the scope report's stand-ins (DRA-126, Values needed), quoted so the checks can be read on the canvas; if the committed files hold other values, read the check with those. Grey is (128, 128, 128).
- The after-save look, the 1-px slot lines and the leaderboard's columns are the stand-ins in `systems/game-flow.md`, Presentation (from docs/reports/DRA-126-away-log.md, Decisions, 4 and 5). Empty storage is a working, empty list (`save-storage.md`, load_saves step 2).

Source: systems/game-flow.md, Rules (GAME_OVER); save-storage.md, write_saves; systems/hud.md, BEST line; 02-game-flow.md, Edge cases.

- **Empty name (`?debug=1`, preload one strong entry and `"last_nickname": null`):** at game over press Enter at once: `name empty, nothing saved`, no `saves written`, the stored text unchanged, RETRY and MENU white and taking keys. Source: 11-save-data.md, rule 8.
- **Broken saves (`/` and `?debug=1`):** preload, one at a time, `not json`, `{"entries": []}` (no `last_nickname`), and two entries out of order. Each time: WARNING `saves off reason=broken error=...` naming the problem, no BEST, game over shows `GAME OVER` with no picker, the leaderboard shows `No scores yet.`, and after a full run the stored text is exactly what was preloaded. No error screen. Source: save-storage.md, load_saves step 3; 11-save-data.md, rule 5.
- **Storage blocked:** before the click, make reading `window.localStorage` throw (`browser_evaluate` redefining it). Then: WARNING `saves off reason=storage ...`, the game runs as with broken saves. Report the Python exception class pygbag delivered. If the page can't be set up this way, say so and why. Source: save-storage.md, load_saves step 1 and Errors.
- **Write fails:** with a list loaded, make `Storage.prototype.setItem` throw, then save a top-10 name: WARNING `saves off reason=write ...`; the screen stays as it is; after RETRY, no BEST, and the next game over shows GAME OVER with no picker. Report the exception class. Source: save-storage.md, write_saves; systems/game-flow.md, stop_saves.
- **Debug saves the same:** save a name in `?debug=1`, then open `/` in the same browser: the same list and BEST. Source: 91-decision-log.md, row 93.
- **Desktop (headless, `SDL_VIDEODRIVER=dummy`):** `run()` logs INFO `saves off reason=desktop` and starts with no error; no file is written anywhere. Source: save-storage.md, Where saves work.
