## Rules

Integration checks for DRA-117, on top of the required browser checks and every earlier check, as reworded below (all must still pass). Each check starts in a fresh page unless it says otherwise. Background:
- `game/tuning/scoring.json` exists and holds the GDD's graze values (06-scoring.md, Values), each key as `docs/contracts/schemas/scoring.schema.json` names it.
- `game/tuning/hazards.json` may leave `graze_margin` out (the default is the GDD's) or set it to the GDD's value.
- The committed `game/tuning/debug_spawns.json` keeps its other rows, its `play`, `mode` and `loop_ticks`, and gains this meteorite row, last among the meteorite rows: `{"type": "meteorite", "x": 357}` (the default medium rock, falling past the right side of a ship held on the top line at x 320: its circle stays 7 px clear of the ship's foot, while its graze zone overlaps the foot).

Checks marked **(meteorite mode)** need `"play": "list"` and `"mode": "meteorite"` in that file: the Director switches them, or allows the Integration Engineer to switch them for the run and put them back after. In that mode the four meteorite rows play in file order (x 160 small, x 320 medium, x 480 big, x 357 medium) and loop. With ArrowUp held from play start the ship sits on the top line at (320, 184); with no key held it falls on tick 64 and then waits at (320, 240). Every graze color is white (255, 255, 255), the same as the placeholder ship and the HUD, so the checks read the popup and the ring where the ship isn't drawn. Ticks are the run's own; times are ticks ÷ 60. Positions are on the 640 × 480 canvas.
