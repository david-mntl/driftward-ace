## Observations
1. **Click outside the canvas doesn't pause.**
   - What happened: during play, moving focus from the canvas to the page body (`canvas.blur()`, a trusted element blur, plus a click on the body at (80, 360)) gave no pygame event and no pause. The window keeps focus, so SDL sends nothing.
   - Why it fits the docs: 02-game-flow.md, rule 7 pauses when "the browser tab or window" loses focus, and frame-loop.md (Focus) names "a click outside the page". Both are window blurs, and a window blur delivers `WindowFocusLost` and pauses.
   - The gap: integration-checks/DRA-125.md asks for "click outside the canvas" and expects a pause.
   - Proposed wording for the Architect: "click outside the page (another window)".
   - Effect: no code change is needed for the GDD rule.
2. **A key held through start became a press in the test browser.**
   - What happened: Space held with key repeat from page load picked Play. SDL's first KEYDOWN reached the game about 100 ms after the frame loop started, after its first ticks had read the key as up.
   - What it means: `start_flow` treats every key as held, but SDL hadn't reported the key yet, so it counted as a fresh press. Core and the app follow the contract.
   - Why it's an Observation: this is a click-to-start result (method.md), which only a desktop browser shows truly. The Director should hold Space through pygbag's click there.
   - If Play is picked there too: it breaks 02-game-flow.md, rule 12, and the fix is a contract change, not a file fix.
3. **Synthetic focus events.** pygbag logs `221: DISCARD : blur {'isTrusted': False}` for my dispatched blur and focus events, but SDL still turns the blur into `WindowFocusLost`. SDL sends it only once until a focus-gained event, so later blurs did nothing until I dispatched `focus`. A real tab switch sends focus on return, so this should not matter in play.
4. **Real tab switch not shown.** The headless browser keeps both tabs visible and focused, so the window-blur stand-in was used, as the check allows.
5. **pygbag leave-page prompt.** Reloading a running page raised pygbag's beforeunload confirm ("Are you sure you want to navigate away"). The browser blocked it and logged one console error. It comes from pygbag's page, not the game. I closed and reopened the tab instead.
6. **Text matched by ink size, not an in-page render.**
   - Each text's ink box was compared with pygame-ce 2.5.8's default font rendered on the desktop.
   - Exact matches: heights everywhere; widths of `Play`, `GAME OVER`, `RETRY` and `MENU`.
   - Within 2 to 9 % narrower: `DRIFTWARD ACE`, `Instructions`, `Leaderboard`, `PAUSE`, the footer. This is the browser's pygame-ce 2.5.7 font difference the DRA-117 report describes.
   - Not read word for word: the six instruction lines.
7. **Earlier drifter checks not re-run one by one.** Their code didn't change in this feature, and `check.sh` passes.
8. **Waves hit the waiting ship.** In debug mode the spawn list plays waves (`play=waves`). Wave 0's meteorites at x 320 hit a ship waiting at the respawn point, so idle runs end in about 10 s. This is expected behavior, noted because it shaped how the checks were timed.

## Decisions
- **Load order:** `load_tuning()`, `load_graze_rules()`, `load_last_life_rules()`, `load_wave_book()`, then the spawn list in debug mode. The contract puts the last-life load "right after `load_graze_rules()`", and the check wants `last life loaded` right after `scoring loaded`. Source: frame-loop.md, Rules (DRA-125); integration-checks/DRA-125.md (Tuning loaded).
- **One wrap, no second run:** `flow = start_flow(start_run(waves=..., graze_rules=..., last_life_rules=...))` once. The app never calls `start_run` again, nor `step_run`, `next_run` or `add_drifters`. Source: frame-loop.md, Rules.
- **Input per frame:** `_held_keys()` reads `get_pressed()` once and returns the `Thrust` and `confirm` (any of K_RETURN, K_KP_ENTER, K_SPACE). Every tick in the frame uses both. The app never works out a fresh press. Source: frame-loop.md, Held keys and Confirm keys.
- **Focus:** a focus-lost event in the frame sets `focus_lost_pending`. The first tick gets `focus_lost=True`, then the flag clears. If a frame runs no tick, the flag carries to the next frame. Source: frame-loop.md, Focus and Tick.
- **Tick:** one `step_flow`, then `add_flow_drifters` with the spawn list's due rows when it plays, else `flow.run.wave_spawns_due`. The 60 Hz accumulator and the 5-tick cap are unchanged. Source: frame-loop.md, Tick and Catch-up cap; 15-tech-constraints.md, rules 1 and 2.
- **Draw by screen:** background, then the menu, instructions or leaderboard alone. On playing, paused and game over, the world in its old order, with:
  - `draw_burst` in the ship's place while `run.last_life`;
  - the overlay;
  - `draw_pause_box` on PAUSED, or `draw_game_over`, `draw_final_score`, `draw_game_over_choices` on GAME_OVER (by `flow.screen`, not `run.game_over`);
  - the HUD last.
  Source: frame-loop.md, Draw; release.md (DRA-125 calls); game-flow.md, Presentation.
- **Key log:** arrows and confirm keys share one map, so both log `key down/up key=<name> x= y=` with `flow.run.ship`, on every screen. Source: frame-loop.md, Arrow keys and Confirm keys log.
- **Last-life loader:** `check_fields` with every field optional. `last_life_delay`, `burst_particle_count` and `burst_particle_size` go through `check_integer(..., 1)`. `burst_particle_speed` is a number >= 0, never a bool. Defaults are the `DEFAULT_*` constants imported from `core.last_life`; the loader keeps no copy. Source: tuning-loader.md, Rules (Last life file); last-life.schema.json.
