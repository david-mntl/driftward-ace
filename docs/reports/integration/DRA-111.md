## Decisions
- **Loader order:** I check the file's fields first, then `speed_ratio` (>= 0), `entry_warning_ticks`, `fill_opacity` (> 0 and <= 1), and the cycle and look values (`charge_ticks`, `fire_ticks`, `charge_rays` ints >= 1; the four widths > 0). Then the variants (`ball_size` an even int >= 2, `pulse_radius` an int >= 1), each passing `check_electric_ball_variant`. Then `default_variant`. This is the same shape as `_load_ufo`, so a broken value is named before the core rule runs. A core message is raised as `<file>: variants.<name>: <core message>`, `from` the core error. Source: tuning-loader.md, Rules (The electric ball's file).
- **Records:** for each variant, `VariantTuning(width=float(ball_size), height=float(ball_size), hitbox=electric_ball_hitbox(float(pulse_radius)), extra=ElectricBallVariantExtra(pulse_radius=float(pulse_radius)))`. For the type, `ElectricBallTypeExtra` with floats for the px values and the opacity. There is no footprint check, because the pulse circle lies outside the ball by design. Source: tuning-loader.md, What the loader builds for the electric ball.
- **Shared checks reused:** `check_even_size`, `check_integer`, `check_positive`, `check_number`, `check_warning_ticks`, `check_variant_name` and `is_number` from `app.drifters.checks`, so each field rule has one home and the messages match the other drifter files. Source: systems/app/general.md, Interface (`app/drifters/checks.py`).
- **No change to the frame, the loop or the spawn list code:** electric balls come in through `add_drifters` and the debug rows, and are drawn by `render_drifter`. The loop stays a fixed 60 Hz accumulator with `await asyncio.sleep(0)` each frame. Source: DRA-111 impact.md; 15-tech-constraints.md.
- **Ball-mode checks on the committed spawn list:** the main session had already put the file in ball mode, so I ran every ball-mode check on the real build and didn't edit the file. The headless bad-file cases used a scratch copy of `game/tuning/` in the scratchpad, with `app.tuning.TUNING_DIR` pointed at it. Source: integration-checks/DRA-111.md.
- **Logging:** nothing new. The loader logs nothing itself; `app.tuning` logs its one INFO line at startup. Nothing logs per tick. Source: game/CONTEXT.md, Logging.
