## Summary
The HUD is a side panel in the ship's hull, to the right of the play area. It shows the score as digit tiles with a progress bar and the best score, the lives as hearts on a wireframe of the ship, the level as a number with climb bars, and the grazes on a radar dial. The play area sits behind a cockpit window frame. The menu leads to the run, the instructions, the leaderboard and the credits. The pause box shows while the game is paused. The game-over screen shows the result and how to retry. Every hazard warning on screen is part of the hazard's spec, not the HUD.

```
 window 856 × 518
 +----------------------------------+-+----------------+
 |  cockpit frame                   |p| SCORE  tiles   |
 |  +---------------------------+   |i| bar    BEST    |
 |  |                           |   |l|                |
 |  |  play area 640 × 480      |   |l|  hull wireframe|
 |  |  (glass, nothing over it) |   |a|  with 5 hearts |
 |  |                           |   |r|                |
 |  +---------------------------+   | | LEVEL | GRAZE  |
 |                                  | | bars  | dial   |
 +----------------------------------+-+----------------+
```

## Rules
1. **The HUD never covers the play area.** It lives in the panel and the frame, so it can't hide a hazard or a warning (Pillar 2). The debug overlay sits inside the play area, so the two never overlap.
2. HUD shows: score, best, lives, level and grazes, as the rows above say. BEST appears once the top 10 has an entry ([11-save-data.md](11-save-data.md)).
3. While invulnerable, the ship blinks ([05-lives-and-damage.md](05-lives-and-damage.md)).
4. **Life-lost feedback** (screen flash, HUD life breaks, ship burst and rebuild) is defined in [05-lives-and-damage.md](05-lives-and-damage.md) rule 3. Its look and timings live here once set: LD-08.
5. The UI only reads game state. It never changes it.
6. All in-game text uses a direct, human voice. Short sentences, no filler, no hype. In the `ui_voice`: terse, except the `menu_hint`. Words fixed in a locked row (PAUSE, RETRY, NEW BEST SCORE, TOP 3, TOP 10, GAME OVER) stay as written. Source: Director.
7. **Debug overlay.** Exists only in debug mode ([15-tech-constraints.md](15-tech-constraints.md) rule 7). It only reads game state, like the HUD. In normal mode it never shows and F3 does nothing. In debug mode a debug setting chooses what plays: the normal waves or the test spawn list (the list when left out).
8. **Error screen.** Replaces the game when an unexpected error stops it. The game doesn't resume; the player reloads the page.
9. **Screens.** When each screen shows and which keys it takes: [02-game-flow.md](02-game-flow.md). The content of each is fixed above, and `window_screens` says where each sits; the text and look are in `instructions_text_and_look`, `screens_look` and the rows after it.
10. **Game-over message.** Only the message for the run's place shows ([11-save-data.md](11-save-data.md) rule 10). A score off the list never says it made the top 10 or is a new best.
11. **Cheap to draw.** The frame and the panel's art are drawn ahead of time and shown as images. Per frame only values change: ten digit images are made once and 7 tiles are shown; the sweep, the scan line, the heartbeat and the rings are frames made ahead of time. Source: [15-tech-constraints.md](15-tech-constraints.md) rule 5.
12. **Every HUD value is configurable**: colors, sizes, positions, counts and timings. The values above are starting points.
13. **Start page.** It never draws over the running game: it fades out and goes. It has no menu and no other keys. If the player has reduced motion set in the browser, the fade-in, the rule's draw-out and the pulse are off. Source: Director.
14. **Level-up banner.** The one piece of UI drawn on the play area during play, besides the points popups. It plays only in the level-up rest, never while a wave plays. It sits behind the drifters, their warnings, the popups and the ship, so it never hides anything the player must see (Pillar 2). Only the number's short flight into the HUD passes over them. It freezes on pause. If the last life is lost, it stops at once. Its picture bump never moves a hitbox or the ship. No solid fuchsia ([12-art-and-audio.md](12-art-and-audio.md) rule 6) and no blur glow.

## Edge cases
- Very large scores: the tiles stop at 9 999 999. The score itself keeps counting.
- Very large graze counts: the number shrinks to fit inside the dial.
- A level above 8 is not possible ([08-difficulty.md](08-difficulty.md) rule 1); if it ever showed, all bars stay lit.

## How to extend
A new HUD element needs a position, the game state it reads, and its update rule. If the game doesn't track that state yet, adding it is a game-logic change, not a UI one.
